# Что можно вычистить, а что сломается

Когда захочется оставить в репозитории только приложение — вот
что уйдёт безболезненно, а что утащит за собой работающие вещи.

Ничего не удаляйте до того, как приложение пройдёт модерацию:
пока карточку заполняете, половина этих папок вам ещё нужна.

---

## Удаляется свободно

| Что | Размер вопроса | Что потеряете |
|---|---|---|
| `АВТОРУ/` | эта папка | все инструкции, тексты постов, план монетизации. Сохраните себе копию — восстановить будет неоткуда |
| `apps/vk-bot/` | бот | он не запущен ни разу. Если решите, что рассылки не будет — удаляйте вместе с упоминаниями в `README.md` и `CLAUDE.md` |
| `tools/vk-docs/` | скрипты конвертации | только если удаляете и саму базу знаний: без неё они бессмысленны |

## Удаляется с последствиями

**`docs/vk/`** — 499 страниц документации ВК. Приложение без неё
работает, но:

- отвечать на вопросы по платформе придётся по памяти или по сайту,
  а память про VK Bridge врёт;
- `CLAUDE.md` прямо велит искать ответы там — правило станет мёртвым,
  надо будет убрать и его;
- папка большая, но она текстовая: на скорость сборки и вес готового
  приложения не влияет вообще. Пользователь её не скачивает.

Удалять её ради «чистоты» смысла нет. Ради приватности — тоже:
это публичная документация ВК, ничего вашего в ней нет.

**`scripts/brand/`** — генераторы иконок, обложек, сторис и скриншотов.
Удалите — картинки в `apps/vk-audit/docs/brand/` останутся, но
пересобрать их после правки интерфейса будет нечем. Рисовать заново
руками дороже, чем держать три файла.

## Не трогать

| Что | Почему |
|---|---|
| `scripts/collect-dist.mjs` | его вызывает `npm run build`; без него сборка не доедет до `dist/` и хостинг отдаст пустоту |
| `.github/workflows/` | это и есть публикация на GitHub Pages. Удалите — сайт перестанет обновляться |
| `LICENSE` | единственное, что отделяет «код открыт» от «код можно брать» |
| `apps/vk-audit/docs/brand/` | картинки для каталога; ВК хранит загруженные копии, но исходники нужны при обновлении |
| `apps/vk-audit/src/engine/__fixtures__/` | эталоны расчёта. Заодно это ваши отпечатки для доказательства авторства — см. `АВТОРСТВО.md` |

## Порядок, если всё-таки чистить

1. Скопируйте `АВТОРУ/` себе на диск — там всё, что не восстановится.
2. Удаляйте по одной папке, **между удалениями** прогоняйте:

```bash
npm run build && npm test
```

Сборка и 44 проверки должны проходить. Если что-то отвалилось —
удалили лишнее, откатывайтесь: `git checkout HEAD~1 -- <папка>`.

3. Почистите ссылки в `README.md` и `CLAUDE.md`: битые ссылки в корне
   выглядят хуже, чем лишняя папка.

**Всё удалённое остаётся в истории git.** Чистка репозитория —
это про порядок на витрине, а не про то, чтобы информация исчезла:
любой, кто клонирует репозиторий, достанет её из старых коммитов.
Если нужно именно стереть — это переписывание истории, отдельная
операция, и она ломает все существующие клоны и форки.
