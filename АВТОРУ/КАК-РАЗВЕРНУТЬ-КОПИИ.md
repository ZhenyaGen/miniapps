# Две копии: шаблон и бэкап

Создавать репозитории у меня прав нет — GitHub App их не выдаёт.
Поэтому шаблон собран файлом, а бэкап делается двумя командами.
Обе операции ваши, займут пару минут.

---

## 1. Шаблон для новых приложений

В архиве `vk-miniapp-template.zip` — готовый репозиторий с уже
сделанным первым коммитом. Внутри: пустое приложение на VKUI
с работающим входом, база знаний `docs/vk` (499 страниц), генератор
иконок и обложек, публикация на GitHub Pages.

Приложения «Аудит страницы ВК» там нет: движок, правила и эталоны
остались в основном репозитории.

**Как развернуть:**

1. Распакуйте архив.
2. Создайте пустой репозиторий на GitHub — например `vk-miniapps`.
   **Без** README, .gitignore и лицензии: они уже внутри.
3. В папке распакованного шаблона:

```bash
git remote add origin https://github.com/ZhenyaGen/vk-miniapps.git
git push -u origin main
```

4. Settings → Pages → Source → GitHub Actions — и приложение
   начнёт публиковаться при каждом пуше.

Дальше — по `README.md` внутри: семь шагов от номера приложения
до карточки в каталоге.

**Проверено:** приложение собирается (`npm install && npm run build`
внутри `apps/app`), 4083 модуля, ошибок нет.

## 2. Бэкап основного репозитория

Полная копия со всей историей — на случай, если с основным что-то
случится, и как площадка, где можно ломать, не трогая рабочее.

1. Создайте на GitHub пустой репозиторий `miniapps-backup`,
   видимость — **приватный**.
2. В папке основного репозитория:

```bash
git remote add backup https://github.com/ZhenyaGen/miniapps-backup.git
git push --mirror backup
```

`--mirror` переносит **все** ветки и теги, включая рабочую
`claude/vk-mini-apps-knowledge-base-kos6be`. Обычный `push` этого
не делает.

**Обновлять потом** — той же одной командой:

```bash
git push --mirror backup
```

Автоматически это делать не стоит: бэкап ценен именно тем, что
отстаёт. Если в основном что-то сломается и уедет туда же сразу —
восстанавливать будет не из чего.

---

## Что во что не превращается

Шаблон и бэкап — разные вещи, и объединять их не надо.

**Бэкап** повторяет основной репозиторий целиком, включая аудит.
Он для восстановления, а не для разработки: коммиты туда не делайте,
иначе при следующем `--mirror` они пропадут.

**Шаблон** — стартовая точка. Каждое новое приложение начинается
не в нём, а в его копии: создали репозиторий из шаблона, переписали
первый экран, поехали. Сам шаблон правьте только тогда, когда
улучшение пригодится всем будущим приложениям.
