# Загрузка и публикация тестовых сборок

**Раздел:** VK Testers → Открытый API → Загрузка и публикация тестовых сборок  
**Источник:** документация VK для разработчиков (dev.vk.com)

---

С помощью платформы VK Testers можно раздавать тестовые версии мобильных приложений. Каждая сборка прикрепляется к версии продукта и доступна всем его участникам.

Загрузка сборок доступна только для продуктов соответствующего типа и платформы: APK- файлов для мобильных приложений для Android и приложений Smart TV с Android TV, IPA- файлов — для iOS.

## Автоматическая загрузка

В настоящий момент поддерживаются файлы в формате IPA и APK.

Чтобы загрузить файлы:

1. Получите ссылки для загрузки сборки с помощью метода [`bugtracker.getProductBuildUploadServer`](https://dev.vk.ru/ru/method/bugtracker.getProductBuildUploadServer) с [ключом доступа](https://dev.vk.ru/ru/vk-testers/access-tokens) компании или продукта. Например:

```bash
curl -X GET
'https://api.vk.ru/method/bugtracker.getProductBuildUploadServer' \
  -H 'Authorization: Bearer <КЛЮЧ_ДОСТУПА>' \
  -F 'v=5.199' \
  -F 'product_id=<ИДЕНТИФИКАТОР_ПРОДУКТА>' \
  | sed -E 's/.*"upload_url":"?([^,"]*)"?.*/\1/' \
  | sed 's/[\\]//g'
```

2. Отправьте файл сборки с помощью POST-запроса по полученной ссылке. Например:

```bash
curl -sSv --http1.1 \
  -F "file=@MyApp.ipa" \
  -F "title=MyApp version 1.0" \
  -F "release_notes=Fixed all issues." \
  "${upload_url}"
```

### Поддерживаемые параметры запроса

| Параметр | Описание |
|---|---|
| `file` | Файл сборки в формате IPA или APK размером не более 4 Гб. |
| `title` | Название сборки. |

**Параметр | Описание**

`version` Режим публикации сборки:
- `1` – создавать скрытую версию продукта.
- `2` – создавать и публиковать версию продукта. Если не передавать этот параметр, будет использоваться настройка продукта.

`release_notes` Текстовое описание сборки.

`set_rft` Информация о том, перевести ли все отчёты, находящиеся в статусе Исправлен, в статус Готов к тестированию. Возможные значения:
- `1` – перевести все отчёты продукта, находящиеся в статусе Исправлен, в статус Готов к тестированию.

### Ответ в формате JSON

| Поле | Описание |
|---|---|
| `build` | Номер сборки, автоматически извлечённый из файла. |
| `bundle` | Строка из ключа `CFBundleIdentifier` для IPA-файла или строка из поля `name` для APK-файла. Строка извлекается автоматически, в случае ошибки извлечения отдаётся пустая строка. |
| `title` | Название сборки, автоматически извлечённое из файла. |
| `version_id` | Числовой идентификатор созданной версии. |
| `version_url` | Ссылка на просмотр созданной версии. |
| В результате успешного выполнения в продукте будет создана скрытая или опубликованная версия | с прикреплённой к ней сборкой. |

Пример ответа:

```json
{
    "build":13450,
    "bundle":"mycompany.myapp",
    "title":"MyApp version 4.12",
    "version_id":34,
    "version_url":"https://vk.com/bugs?act=pversion&id=99987&v=34"
}
```

## Ручная загрузка

Чтобы вручную загрузить сборку:

1. Откройте страницу продукта.

2. В блоке Версии нажмите Загрузить.

После публикации в продукте будет создана скрытая или опубликованная версия с прикреплённой к ней сборкой.

## Состояния сборки

## • Скрыта. Прикреплена к скрытой версии. Скачать скрытую сборку могут участники продукта с уровнем прав разработчик и менеджер. • Опубликована. Прикреплена к опубликованной версии – доступна для скачивания всем участникам продукта. • Отозвана. При наличии в сборке проблем разработчик может отозвать её. Отозванную сборку могут скачать только участники продукта с уровнем прав разработчик и менеджер. Описание версии продукта, к которой прикреплена сборка, доступно всем. • Удалена. Сборка недоступна для скачивания и не занимает хранилище. Сборка удаляется автоматически при удалении версии, к которой она прикреплена, и при удалении продукта, в который она загружена.

## Номер сборки

При загрузке тестовой сборки в продукт из неё автоматически извлекается числовой идентификатор, называемый номером сборки.

В файлах IPA используется значение [`CFBundleVersion`](https://developer.apple.com/documentation/bundleresources/information_property_list/cfbundleversion/). В файлах APK используется значение

[`versionCode`](https://developer.android.com/studio/publish/versioning) [.](https://developer.android.com/studio/publish/versioning)

## Правила учёта номеров сборок

- Номер сборки уникален в рамках продукта – в продукте всегда доступна одна сборка с конкретным номером.
- Если загрузить в продукт сборку с уже существующим номером, она заменит собой существующую.
- При загрузке сборки с идентичным номером поверх отозванной производится возврат сборки в опубликованное состояние.

## Хранилище сборок

Хранилище сборок компании содержит в себе все сборки, загруженные в продукты этой компании. Размер хранилища зависит от подключенного [тарифа](https://mcs.mail.ru/vk-testers/#price) и дополнительных опций компании.

Чтобы посмотреть состояние хранилища:

1. Откройте страницу управления компанией.

2. В боковом меню перейдите на вкладку Сборки.

На вкладке Сборки доступна информация о суммарном размере загруженных сборок, общем размере хранилища, а также количестве и размере сборок, загруженных в каждый продукт компании.

Загрузка сборки в продукт доступна только при условии, что в хранилище достаточно свободного места. Для увеличения доступного места необходимо удалить ненужные сборки

или расширить хранилище, подключив другой тариф или опцию увеличения хранилища.
