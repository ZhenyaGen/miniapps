# vk-audit-bot · разборы страницы в личные сообщения

Бот сообщества: следит за страницей ВКонтакте и раз в неделю, раз в две
недели или раз в месяц присылает в личные сообщения разбор — что выросло,
что просело и что делать дальше. На вопросы по разбору отвечает прямо
в переписке. Текст пишет DeepSeek, цифры считает тот же движок, что
и мини-приложение.

## Как это работает

```
Long Poll ─┬─ сообщение от человека → команда → ответ
           └─ «разрешил сообщения»  → подписка сразу, адрес страницы в key

каждые 15 мин: кому пора → собрать данные → посчитать → DeepSeek → отправить
```

**Числа и текст разделены.** Метрики и зоны роста считает движок из
`apps/vk-audit/src/engine` — он импортируется напрямую, а не копируется, так
что разбор в личке сходится с отчётом в приложении. DeepSeek получает готовые
цифры и системный промпт, который прямо запрещает их выдумывать и округлять.
Если ключа модели нет или она не ответила, письмо всё равно уходит — сухими
фактами: человек ждёт разбор, а не извинения.

**Два ключа доступа.** Ключом сообщества бот пишет сообщения, сервисным —
читает стены: `wall.get` ключу сообщества недоступен, ВК отвечает ошибкой 27.
Оба живут в окружении, в репозиторий не попадают.

## Команды в переписке

| Написать | Что будет |
|---|---|
| ссылку на страницу | начну следить и пришлю первый разбор |
| `неделя` / `две недели` / `месяц` | как часто присылать |
| `разбор` | собрать прямо сейчас |
| `статус` | что настроено |
| `стоп` | отключить рассылку |
| **любой вопрос** | отвечу по цифрам последнего разбора |

Последняя строка — не украшение. Всё, что длиннее восьми знаков и не
похоже на команду, уходит модели вместе с фактами прошлого разбора:
«почему упали просмотры», «о чём написать на этой неделе», «стоит ли
пробовать видео». Ответ считается по тем же числам, что человек уже
прочитал, поэтому разойтись с письмом он не может. Без подключённой
модели бот честно говорит, что отвечать не умеет, — выдумывать ответ
про чужую страницу нельзя.

## Что в разборе

Первым идёт движение, а не срез: **победы и поражения** за последнее
окно против предыдущего такого же. Отчёт в приложении показывает,
какая страница сейчас, — это подписчик и так знает. Ему нужно, что
изменилось.

Окно равно периоду подписки, но не короче двух недель: на меньшем
сроке один удачный пост переворачивает картину. Изменения меньше 12%
не показываются вовсе — это шум. Если в окне меньше трёх постов,
бот прямо пишет, что сравнение приблизительное, и то же самое
сказано модели в промпте.

**Ниша определяется заново каждый раз** — по категории сообщества,
описанию, хештегам и словам собственных постов. Под неё настраивается
системный промпт: правила в нём те же (числа только из данных,
без markdown), меняются словарь и примеры. Совет «добавьте
сторителлинг» одинаково бесполезен автосервису и психологу, но
по-разному. Если сигналов не хватило, ниша остаётся пустой
и промпт — общим: угадывать по названию бот не будет.

**Два разных письма под две ситуации.** Если с прошлого раза ничего
не выросло, а советы уже были, — бот не придумывает новых задач,
а напоминает про старые и предлагает самый маленький шаг. Список,
который растёт быстрее, чем до него доходят руки, — это то, из-за
чего от таких рассылок отписываются.

**Длинная дистанция.** Каждый разбор дописывается в историю, последние
двенадцать точек. Начиная с четвёртой бот сравнивает первую треть ряда
с последней: пара соседних значений не отличает тренд от качелей,
ER мог упасть и вернуться.

Подписаться можно и не открывая переписку: в мини-приложении на вкладке
«Сводка» есть кнопка «Получать разборы в личные». Она вызывает
`VKWebAppAllowMessagesFromGroup` и кладёт адрес страницы в поле `key` —
бот получает его вместе с событием `message_allow` и заводит подписку сразу.

Рассылка законна: по [документации ВК](https://dev.vk.ru/ru/widgets/allow-messages)
после согласия пользователя сообщество может писать ему без ограничения
по срокам. Запрет (`message_deny`) бот тоже слышит и сразу выключает рассылку.

## Перед первым запуском — обновить политику

Пока бот не работает, страница политики конфиденциальности
(`apps/vk-audit/public/privacy.html`) прямо говорит: приложение **не отправляет
сообщений и не ведёт подписок**. Это правда ровно до того дня, когда вы
поднимете бота.

Перед запуском исправьте раздел «Рассылка разборов»: убрать оговорку
«пока не работает» и перевести формулировки из будущего времени
в настоящее. Иначе документ будет описывать не то, что происходит
на самом деле, — а это и есть претензия, с которой приходят к владельцу
приложения.

Там же в приложении заполните `VITE_VK_BOT_GROUP_ID` — без него блок
подписки на вкладке «Сводка» не показывается.

## Запуск по шагам

Порядок такой, чтобы первое живое сообщение вы прочитали раньше,
чем его получит человек.

```bash
npm install
cp .env.example .env    # заполнить ключи; BOT_DRY_RUN=1 там уже стоит
```

**1. Проверить ключи и связь** — ничего не отправляет и не сохраняет:

```bash
npm run check
```

Четыре проверки по отдельности: ключ сообщества, включён ли Long Poll,
читает ли сервисный ключ стены, отвечает ли DeepSeek. Когда бот молчит,
причина обычно одна из этих четырёх, а в общем логе они выглядят
одинаково — поэтому и разведены.

В сообществе перед этим: **Управление → Дополнительно → Работа с API →
Long Poll API → Включено**, версия API 5.199, а в «Типах событий»
отмечены `message_new`, `message_allow` и `message_deny`.

**2. Прочитать, что бот напишет:**

```bash
npm run preview -- vk.com/my_group
npm run preview -- vk.com/my_group месяц
```

Собирает настоящий разбор по указанной странице и печатает его целиком.
В подписки не пишет, никому не отправляет. У модели бывает своё
представление о том, что такое «коротко и по делу» — это место, где
вы об этом узнаёте.

**3. Запустить без отправки:**

```bash
npm start               # при BOT_DRY_RUN=1 сообщения идут в лог
```

Бот слушает Long Poll, отвечает на команды, ведёт подписки и отрабатывает
расписание — не делает ровно одного: `messages.send`. Напишите ему сами
из другого аккаунта и посмотрите в логе, что он ответил бы.

**4. Включить отправку** — убрать `BOT_DRY_RUN` из `.env` и перезапустить.
До этого шага обязательно сделайте то, что описано в разделе ниже про
политику конфиденциальности.

```bash
npm test                # 43 проверки без сети
npm run typecheck
```

Подписки лежат в `data/subscriptions.json` — там идентификаторы живых
людей, и папка `data/` в `.gitignore`. Не выносите её в репозиторий.

## Что где лежит

| Файл | Зачем |
|---|---|
| `src/index.ts` | точка входа: Long Poll и планировщик |
| `src/bot.ts` | ответы на команды, отправка разбора, обработка отказов |
| `src/digest.ts` | сбор данных, факты для модели, запасной сухой текст |
| `src/deepseek.ts` | клиент DeepSeek с системным промптом |
| `src/store.ts` | подписки в JSON-файле и расписание |
| `src/longpoll.ts` | разбор событий сообщества |
| `src/vk.ts` | серверный клиент VK API и нарезка длинных сообщений |
| `src/engine.ts` | реэкспорт движка из мини-приложения |
| `src/check.ts` | проверка ключей и связи перед первым запуском |
| `src/preview.ts` | предпросмотр разбора: собрать и напечатать, не отправляя |
| `src/compare.ts` | победы и поражения за окно, тренд на длинной дистанции |
| `src/niche.ts` | определение ниши и системный промпт под неё |

## Устойчивость

- Long Poll переподключается сам: обрыв связи и протухшая сессия не роняют бота.
- Если страница закрылась или удалена, человек получает сообщение с причиной;
  после третьей неудачи подряд рассылка встаёт на паузу, чтобы не спамить.
- Сообщения длиннее 4000 знаков уходят частями по границам абзацев.
- Подписки пишутся атомарно (временный файл + переименование) — падение
  в момент сохранения не оставит обрезанный JSON.

## Проверено и не проверено

Тестами закрыты команды, расписание, нарезка сообщений, разбор событий Long
Poll, полный сценарий подписки на подставном API — от «пришёл адрес» до
«второй разбор сравнивает с прошлым» — режим без отправки и вся новая
арифметика: что рост не путается с падением, что колебания меньше 12%
не считаются движением, что молчание называется отдельно, что на двух
постах сравнение помечается ненадёжным, что ровный ряд не выдаётся
за тренд и что история обрезается до двенадцати точек.

**Живого прогона против ВК и DeepSeek не было.** Сетевая политика
окружения, где бот писался, не пускает ни к `api.vk.com`, ни
к `api.deepseek.com`, поэтому проверено всё, кроме собственно сети.
Первые три шага запуска (`check` → `preview` → `start` без отправки)
как раз и придуманы, чтобы эту непроверенную часть вы прошли сами
и на своих глазах, а не узнали о проблеме из жалобы подписчика.

Что вероятнее всего вылезет на живом прогоне:

- **Ошибка 27 на `wall.get`** — в `.env` попал ключ сообщества вместо
  сервисного. Первым это поймает `npm run check`.
- **Long Poll молчит** — включён, но в «Типах событий» не отмечены
  `message_new`, `message_allow`, `message_deny`. Проверка увидит только
  первое, отметки — на вашей совести.
- **Разбор длиннее 4000 знаков** — уедет частями, это штатно, но
  посмотрите на `preview`, не разваливается ли текст по смыслу.
- **Модель пишет не то** — промпт запрещает считать и выдумывать числа,
  но не спасает от многословия. Правится в `PROMPT_TAIL` (`digest.ts`).
