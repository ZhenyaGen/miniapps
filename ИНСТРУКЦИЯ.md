# Инструкция: как запустить и обслуживать

Три части, независимые друг от друга:

1. **[Мини-приложение](#часть-1--мини-приложение)** — аудит внутри ВКонтакте. Работает без сервера.
2. **[Бот](#часть-2--бот-с-разборами)** — присылает разборы в личные сообщения. Нужен сервер.
3. **[Обслуживание](#часть-3--обслуживание)** — обновления, логи, типовые поломки.

Если нужно «просто посмотреть» — [запустите демо](#быстрая-проверка-без-вк) за две минуты,
без приложения ВК и без ключей.

---

# Быстрая проверка без ВК

```bash
git clone <адрес репозитория> miniapps
cd miniapps/apps/vk-audit
npm install
npm run dev
```

Откройте `http://localhost:8910`, нажмите **«Открыть демо-отчёт»**. Это
настоящий расчёт на вымышленном сообществе: те же метрики, зоны роста и план,
что и на живой странице.

Проверить, что расчёт не разошёлся с десктопной версией:

```bash
npm test
```

# Часть 1 · Мини-приложение

## Шаг 1. Создать приложение ВКонтакте

1. Откройте [dev.vk.ru](https://dev.vk.ru/) и войдите под своей страницей.
2. **Создать приложение** → тип **«Мини-приложение (VK Mini Apps)»**.
3. Название — то, что увидят люди в каталоге. Например, «Аудит страницы».
4. После создания откройте **Настройки** и запишите **ID приложения** —
   это число вида `51234567`.

ID приложения не секрет: он виден в адресной строке при любом запуске.
Класть его в репозиторий можно.

## Шаг 2. Указать адреса

В настройках приложения заполните:

| Поле | Что вписать |
|---|---|
| Адрес приложения (URL) | `https://ваш-домен/` — куда вы выложите сборку |
| Адрес для мобильных | тот же адрес |
| Доверенный redirect URI | `http://localhost:8910/callback` |

Третья строка — не для мини-приложения, а для десктопной программы и сборки
под Android: они ловят ключ доступа на локальном порту 8910. Адрес зашит
в `apps/vk-audit/src/oauth.ts`, туда же смотрит dev-сервер, поэтому все три
клиента живут на одном приложении ВК.

> Менять порт можно только одновременно в трёх местах: `src/oauth.ts`,
> настройки на dev.vk.ru и десктопная версия. Иначе ВК ответит
> `redirect_uri is incorrect`.

## Шаг 3. Собрать

Есть два пути: собрать в GitHub (ничего не устанавливая) или у себя.

### Путь А · В GitHub, без установки Node

1. В репозитории: **Settings → Secrets and variables → Actions → Variables →
   New repository variable**.
2. Имя `VK_APP_ID`, значение — номер приложения из шага 1. (Второй раз то же
   самое для `VK_BOT_GROUP_ID`, когда сделаете бота.)
3. **Actions → «Сборка мини-приложения» → Run workflow**.
4. Через минуту внизу страницы запуска появится архив **`vk-audit-dist`** —
   скачайте и распакуйте.

Сборка сама прогоняет тесты и проверяет, что номер приложения попал внутрь:
если переменную забыли задать, запуск покажет ошибку, а не выдаст нерабочий
архив.

### Путь Б · У себя

```bash
cd apps/vk-audit
cp .env.example .env
```

В `.env` впишите ID из шага 1:

```
VITE_VK_APP_ID=51234567
VITE_VK_BOT_GROUP_ID=
```

Вторую строку заполните позже, когда сделаете бота (часть 2) — тогда в отчёте
появится кнопка «Получать разборы в личные». Пусто — кнопки просто нет.

```bash
npm install
npm run build
```

Готовая сборка — папка `dist/`: обычная статика, ничего исполняемого.

## Шаг 4. Выложить

Подойдёт любой хостинг статики с HTTPS — ВКонтакте требует именно `https`.
Проще всего, если своего сервера нет:

| Куда | Как |
|---|---|
| **Netlify** | [app.netlify.com/drop](https://app.netlify.com/drop) — перетащить папку `dist` мышью. Адрес выдаётся сразу, бесплатно, приватный репозиторий не нужен |
| **Vercel** | то же самое, `vercel deploy --prod` из папки `dist` |
| **VK Cloud** | объектное хранилище с публичным доступом — если хочется всё держать в российском облаке |
| **Свой сервер** | см. ниже |

Адрес, который выдаст хостинг (например, `https://vk-audit-abc123.netlify.app/`),
и надо вписать в настройки приложения из шага 2.

**Вариант «файлы на сервер».** Скопируйте `dist/` в папку веб-сервера:

```bash
rsync -av --delete dist/ user@server:/var/www/vk-audit/
```

Конфиг nginx — раздать файлы и отдавать `index.html` на любой путь
(приложение одностраничное):

```nginx
server {
    listen 443 ssl;
    server_name ваш-домен;

    root /var/www/vk-audit;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

Сертификат — `certbot --nginx -d ваш-домен`, бесплатно.

**Вариант «без своего сервера».** Любой хостинг статики (VK Cloud, Netlify,
Vercel, GitHub Pages) — залейте содержимое `dist/`. Сборка собрана
с относительными путями, поэтому работает и в подпапке.

## Шаг 5. Проверить в ВК

Откройте `https://vk.com/app<ID приложения>` — например,
`https://vk.com/app51234567`. Должен открыться первый экран.

Нажмите **«Войти»**: ВКонтакте спросит разрешение на доступ к сообществам
и статистике. После этого подтянется список ваших сообществ — нажмите
любое, чтобы собрать аудит.

## Шаг 6. Отправить на модерацию

Пока приложение не прошло модерацию, оно доступно только вам и тем, кого вы
добавите в тестировщики (**Настройки → Доступ**). Для каталога заполните
описание, иконки и скриншоты и нажмите **«Отправить на модерацию»**.
Требования — в базе знаний: [`docs/vk/rules/`](docs/vk/README.md#rules).

# Часть 2 · Бот с разборами

Боту нужен сервер, который работает постоянно: он слушает сообщения и раз
в 15 минут проверяет, кому пора слать разбор. Подойдёт самая дешёвая VPS.

## Шаг 1. Сообщество

1. Создайте сообщество ВКонтакте (или возьмите готовое).
2. **Управление → Сообщения** → включить.
3. **Управление → Работа с API → Ключи доступа** → создать ключ с правом
   **«Сообщения сообщества»**. Это `VK_GROUP_TOKEN`.
4. **Управление → Работа с API → Long Poll API** → **Включено**,
   версия API — `5.199`.
5. Там же **Типы событий** → отметить **Входящее сообщение**,
   **Разрешение на сообщения** и **Запрет на сообщения**.
6. ID сообщества — число из адреса `vk.com/club123456789` или в настройках.
   Это `VK_GROUP_ID` (без минуса).

## Шаг 2. Сервисный ключ

На [dev.vk.ru](https://dev.vk.ru/) → ваше приложение → **Разработка → Ключи
доступа** → строка **«Сервисный ключ»** → **Показать**. Это `VK_SERVICE_TOKEN`.

Он нужен, потому что ключом сообщества читать стены нельзя — ВК отвечает
ошибкой 27. Сервисный ключ держится только на сервере: в мини-приложение
его класть нельзя, бандл распаковывается.

## Шаг 3. Ключ DeepSeek

[platform.deepseek.com](https://platform.deepseek.com/) → пополнить баланс
(от $2, российские карты проходят) → **API keys** → **Create new API key**.
Это `VK_LLM_KEY`.

Один разбор стоит около рубля. Без ключа бот тоже работает — присылает те же
цифры и зоны роста, только сухим списком, без человеческого текста.

## Шаг 4. Запустить

На сервере нужен Node.js 20 или новее.

```bash
git clone <адрес репозитория> /opt/miniapps
cd /opt/miniapps/apps/vk-bot
npm install
cp .env.example .env
nano .env          # вписать четыре ключа из шагов 1–3
npm start
```

В логе должно появиться:

```
Подписок загружено: 0
DeepSeek на связи: deepseek-chat
Планировщик каждые 15 мин. Слушаю сообщения.
Long Poll подключён
```

Напишите сообществу ссылку на любое открытое сообщество — бот соберёт разбор
и пришлёт его в ответ.

## Шаг 5. Держать запущенным

Чтобы бот поднимался сам после перезагрузки, положите юнит systemd
в `/etc/systemd/system/vk-audit-bot.service`:

```ini
[Unit]
Description=Бот разборов страниц ВК
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/miniapps/apps/vk-bot
EnvironmentFile=/opt/miniapps/apps/vk-bot/.env
ExecStart=/usr/bin/npm start
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now vk-audit-bot
sudo systemctl status vk-audit-bot
```

## Шаг 6. Связать с мини-приложением

Впишите ID сообщества в `apps/vk-audit/.env`:

```
VITE_VK_BOT_GROUP_ID=123456789
```

Пересоберите и выложите приложение (шаги 3–4 первой части). В отчёте на
вкладке «Сводка» появится кнопка **«Получать разборы в личные»**: человек
нажимает её, ВК спрашивает разрешение, и бот сразу заводит подписку на ту
страницу, которую тот смотрел, — переписываться не нужно.

# Часть 3 · Обслуживание

## Обновить

```bash
cd /opt/miniapps
git pull

# приложение
cd apps/vk-audit && npm install && npm test && npm run build
rsync -av --delete dist/ /var/www/vk-audit/

# бот
cd ../vk-bot && npm install && npm test
sudo systemctl restart vk-audit-bot
```

`npm test` перед выкладкой — не формальность: он сверяет расчёт с эталоном
десктопной версии. Если тест упал, значит движки разошлись, и цифры в exe,
APK и мини-приложении перестали совпадать. Чинить нужно расчёт, а не эталон.

## Смотреть логи

```bash
sudo journalctl -u vk-audit-bot -f          # прямо сейчас
sudo journalctl -u vk-audit-bot --since today
```

Что в логе нормально:

| Строка | Значит |
|---|---|
| `Long Poll подключён` | связь с ВК есть |
| `Разбор отправлен 12345 (Название)` | письмо ушло |
| `..., без DeepSeek` | модель не ответила, ушли сухие факты |
| `Плановая рассылка: 3` | по расписанию отправлено три разбора |
| `Long Poll оборвался: … Переподключаюсь` | сеть моргнула, бот сам восстановится |

## Бэкап подписок

Все подписки — один файл `apps/vk-bot/data/subscriptions.json`. Он не в git
(там идентификаторы людей). Копируйте его по расписанию:

```bash
0 4 * * * cp /opt/miniapps/apps/vk-bot/data/subscriptions.json \
             /var/backups/subscriptions-$(date +\%F).json
```

Восстановление — положить файл на место и перезапустить бота.

## Типовые поломки

**`redirect_uri is incorrect` при входе из десктопной версии.**
В настройках приложения нет `http://localhost:8910/callback` или он записан
с опечаткой. Сверьте с `apps/vk-audit/src/oauth.ts`.

**В мини-приложении «Войти» ничего не делает.**
Не заполнен `VITE_VK_APP_ID` или сборка выложена старая. Проверьте
`grep -o 'VITE_VK_APP_ID' -r dist/` — в собранных файлах должно быть само
число, а не имя переменной.

**Бот молчит, в логе `Long Poll оборвался` без остановки.**
Не включён Long Poll API в сообществе или ключ сообщества без права
«Сообщения сообщества». Пересоздайте ключ (шаг 1 второй части).

**`Ключом сообщества стену читать нельзя (код 27)`.**
В `VK_SERVICE_TOKEN` попал ключ сообщества вместо сервисного. Возьмите ключ
из раздела «Ключи доступа» приложения, а не сообщества.

**`Слишком много запросов (код 6)`.**
ВК ограничивает: 3 запроса в секунду пользовательским ключом, 5 и выше —
сервисным. Бот сам ждёт и повторяет, но если подписчиков стало много,
увеличьте `BOT_TICK_MINUTES` — рассылка размажется по времени.

**Разборы приходят без человеческого текста.**
Кончился баланс DeepSeek или сменился ключ. В логе будет
`DeepSeek недоступен`. Проверьте баланс и `VK_LLM_KEY`.

**Статистика сообщества пустая.**
Охваты, демографию и подписки-отписки ВК отдаёт только администратору
сообщества. Для чужих страниц их не будет никогда — это ограничение
платформы, а не программы.

## Сколько это стоит

| Что | Сколько |
|---|---|
| Мини-приложение | бесплатно, статика на любом хостинге |
| Сервер под бота | от 200 ₽/мес, хватает самой маленькой VPS |
| DeepSeek | около 1 ₽ за разбор |
| Приложение и сообщество ВК | бесплатно |

Сто подписчиков с еженедельным разбором — это примерно 400 ₽ в месяц
за модель плюс сервер.

## Приватность

Мини-приложение считает всё в браузере: данные страницы никуда не уходят,
сервера у него нет вовсе. Бот хранит только то, без чего не может работать:
идентификатор пользователя, адрес страницы, периодичность и цифры прошлого
разбора — чтобы написать «было → стало». Тексты постов не сохраняются:
они читаются, считаются и забываются.

Если раздаёте бота другим людям, помните про 152-ФЗ: подписки — это
персональные данные, и сервер с ними должен стоять в России.
