# Конвертация документации VK в Markdown

Скрипты, которыми собрана база знаний в [`docs/vk/`](../../docs/vk/README.md).
Исходник — PDF-экспорт страниц [dev.vk.ru](https://dev.vk.ru) (5 zip-архивов, ~87 МБ).
Сами PDF в репозиторий не коммитятся.

## Запуск

```bash
pip install pymupdf

# 1. распаковать архивы (имена файлов в cp437, unzip падает на длине путей)
python3 tools/vk-docs/extract_pdfs.py <папка-с-zip> _raw

# 2. PDF -> Markdown + docs/vk/index.json
python3 tools/vk-docs/convert.py _raw docs/vk

# 3. README.md и vk-bridge/EVENTS.md по индексу
python3 tools/vk-docs/make_index.py docs/vk
```

## Как это работает

`extract_pdfs.py` разворачивает архивы в плоскую папку: файлы сохраняются под
хешем содержимого, настоящие имена — в `_manifest.json`. Дубликаты (архивы
частично пересекаются: 756 файлов → 499 уникальных) отбрасываются по хешу.

`convert.py` разбирает PDF поблочно через PyMuPDF и опирается на то, что
вёрстка документации одинакова на всём корпусе:

- размер шрифта → уровень заголовка (18 → `##`, 15 → `##`, 12.8 → `###`,
  жирный 11.2 в одну строку → `####`);
- `JetBrainsMono` и мелкий `SegoeUI` → inline-код и блоки ``` с языком,
  который берётся из подписи над блоком (`JavaScript`, `TypeScript`, …);
- блоки на одной горизонтали → строка таблицы; жирный многострочный блок
  над ней → шапка таблицы;
- аннотации-ссылки PDF → markdown-ссылки, `vk.ru/away.php?to=` разворачивается
  в исходный URL;
- служебные элементы страницы (`EN`, «На этой странице», логотип в шапке) и
  повторяющиеся страницы выбрасываются.

Категория и путь файла берутся из хлебных крошек в имени PDF
(`VK Bridge _ Пользователи _ VKWebAppGetGeodata` →
`vk-bridge/polzovateli-vkwebappgetgeodata.md`), заголовки транслитерируются.

Известные дефекты исходного экспорта перечислены в `SOURCE_NOTES` в
`convert.py` — они попадают в шапку соответствующей страницы как предупреждение.
